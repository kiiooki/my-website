驾校信息管理系统数据库：典型查询示例

这份材料基于课程项目报告整理，重点展示我如何把报名、预约、缴费、学时统计与教练绩效等业务场景 抽象成关系模型、约束规则与可复用的 SQL 查询逻辑。相比只展示“建库”，这里更希望体现的是： 我理解业务数据、表关系、视图汇总与典型分析查询如何落到数据库层。

1. 业务与数据结构

核心业务流程

学员报名建档、课程缴费、教练排班、预约训练、学时累计、绩效结算。

  • 学员与课程、缴费记录、训练预约存在一对多关系。
  • 教练与车辆、排班、训练预约、绩效记录存在关联。
  • 预约、学时、财务记录共同支撑业务状态流转与统计分析。

数据库能力点

  • 关系模式设计与 1NF / 2NF / 3NF 规范化分析。
  • 主外键、唯一约束、CHECK 约束等一致性规则设计。
  • 视图、存储过程、触发器支持状态联动与业务汇总。
  • 面向分析需求组织可复用查询，而不是只停留在建表层。

2. 典型查询示例

查询一：预约状态统计

这个查询展示我如何从核心业务表 Training_Session 中提取预约状态分布， 用于快速了解当前预约系统中“已预约 / 进行中 / 已完成 / 已取消”等状态的数量。 

SELECT
  status,
  COUNT(*) AS session_count
FROM Training_Session
GROUP BY status
ORDER BY session_count DESC;
  • 能力点：围绕业务状态做分组统计。
  • 使用场景：运营看板、预约负载观察、异常状态排查。

查询二：学员缴费汇总

这个查询把学员、课程与缴费记录关联起来，统计每位学员在不同课程上的缴费次数与累计金额， 体现的是多表连接、分组汇总与面向业务分析的组织方式。 

SELECT
  s.student_id,
  s.name,
  c.course_id,
  COUNT(p.payment_id) AS payment_count,
  SUM(p.amount) AS total_paid
FROM Student s
JOIN Payment p
  ON s.student_id = p.student_id
JOIN Course c
  ON p.course_id = c.course_id
GROUP BY s.student_id, s.name, c.course_id
ORDER BY total_paid DESC;
  • 能力点：多表连接、业务指标汇总、按学员与课程粒度分析。
  • 使用场景：收费情况统计、课程销售分析、学员财务核对。

查询三：学员学时进度统计

这个查询从 Student_Training_Hours 表按学员与科目汇总训练学时， 展示如何围绕“训练进度”组织数据，而不是只记录原始流水。 

SELECT
  s.student_id,
  s.name,
  sth.subject,
  SUM(sth.hours_completed) AS total_hours
FROM Student s
JOIN Student_Training_Hours sth
  ON s.student_id = sth.student_id
GROUP BY s.student_id, s.name, sth.subject
ORDER BY s.student_id, sth.subject;
  • 能力点：面向业务进度的聚合统计。
  • 使用场景：学员练车进度跟踪、阶段性训练完成情况检查。

查询四：教练绩效计算

这个查询围绕“已完成训练次数”估算绩效奖金，是我在数据库项目中把业务规则转成 可复用 SQL 逻辑的一类代表性例子。 

SELECT
  i.instructor_id,
  i.name,
  COUNT(CASE WHEN ts.status = N'已完成' THEN 1 END) AS completed_sessions,
  COUNT(CASE WHEN ts.status = N'已完成' THEN 1 END) * 50.00 AS estimated_bonus
FROM Instructor i
LEFT JOIN Training_Session ts
  ON i.instructor_id = ts.instructor_id
GROUP BY i.instructor_id, i.name
ORDER BY completed_sessions DESC;
  • 能力点：把绩效规则转成数据库查询逻辑。
  • 使用场景：月度绩效结算、教练工作量比较、奖金估算。
